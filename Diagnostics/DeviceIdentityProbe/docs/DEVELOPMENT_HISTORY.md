# Development history — Initial D multi-input and FFB investigation

This is the persistent engineering record for this branch. Like the OutRun development history, it records what changed our decisions, including failures and unknowns. Milestone reports hold the detailed evidence. Do not rewrite an unperformed check as a pass when summarizing later work.

## Original-game reports and the input boundary

Players reported digital-feeling input, limited support for separate USB controls and excessive force feedback in the original game. Those are attributed reports, not measurements made by this diagnostic. The probe does not fix or tune them.

Source inspection confirmed a narrower architectural fact: `Assets/Scripts/Idas3ControllerDevices.cs` discovers multiple candidates but exposes controls, active profile and wheel identity through one `active` device. Discovery is not the same as simultaneous wheel/pedals/shifter aggregation. The later input design must preserve existing behavior while addressing that boundary explicitly.

## 2026-09-27 — M1-A2 all-device snapshot foundation (local review)

The provider now publishes immutable all-device frames with sequence, inventory and connection generations, sample age, status and nullable valid values. Session tokens keep identical paths, models and duplicate serials separate. Removal/disable events invalidate current lookups immediately; reconnect requires the new connection generation, and a replacement Unity object gets a new token even if its runtime ID is reused. Historical frames remain immutable evidence, not live-input permission. All physical identity remains unresolved; source-labelled description fields and an unimplemented future validated-evidence interface do not invent a Windows association.

Native XInput retains the existing authoritative-family policy. Suppressed Unity XInput mirrors are visible as unavailable in snapshot inventory. Their delayed eligibility does not change legacy ordering or duplicate selector keys. HID endpoints are never suppressed by matching VID/PID or friendly name; unknown HID/XInput aliases and per-slot association remain unresolved. There is no new polling loop, save migration, enrollment, aggregation or FFB change.

101 portable checks passed against production provider/snapshot code, including a differential copy of the reviewed provider for legacy output/selection/controls/choices.
