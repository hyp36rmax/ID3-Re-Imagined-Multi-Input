# M1-A2 — all-device input snapshot foundation

This production foundation publishes the devices already sampled by `Idas3ControllerDevices.Tick`. It does not combine their input into gameplay, change binding/save formats, enroll hardware, resolve physical identity, alter FFB, or replace an input backend. The Controller menu and the single-active-device accessors remain the gameplay path.

## Interface and ownership

- `Idas3ControllerDevices.Snapshot` returns one immutable `Idas3DeviceFrame`. Read it once for an operation; do not read the property repeatedly to assemble a frame. Publication uses a volatile reference swap after copying all endpoint/control samples. Readers never receive mutable provider controls or reusable pooled buffers.
- A frame has a random provider-session UUID, publication sequence, inventory generation, start/completion times from the provider's monotonic clock, publication kind and read-only endpoint list. `Poll` means one complete existing provider tick, not physically simultaneous sampling of independent USB devices. Unity state comes from its existing input buffers; native slots are read sequentially. `Invalidation` publications retain other endpoints' previous samples. Endpoint `SampleSequence` and `SampledAt` distinguish their sample age from the new publication time; they describe a provider read attempt, not the hardware report timestamp.
- An endpoint has an opaque session token, connection generation, backend, reported display label, status/reason, identity evidence and read-only control samples. Each sample retains its device-local path, label, limits, button flag, validity and nullable value. Only `Valid` has a numeric value; `0` is a valid value when actually read. NaN/infinity produce `Invalid` with no value. Failed reads produce `Unavailable`; an unsupported control read produces `Unsupported`. A recognized device with no supported controls reports `UnsupportedControls`. Keyboard/pointer/sensor and other excluded device classes are outside this provider; keyboard input remains on its existing path.
- `frame.TryGetEndpoint(token, ...)` and `endpoint.TryGetControl(path, ...)` support coherent lookups within that historical frame. `provider.TryReadCurrent(token, connectionGeneration, path, ...)` checks one latest publication and rejects absent, suppressed, disconnected, invalid or old-generation samples. `IsCurrent(frame)` detects an outdated publication; it is not a locking lease. Future gameplay consumers should run on the same Unity thread as Tick and use a single current frame.
- Frames are immutable historical records. Holding an old frame cannot grant ongoing live-input validity: after removal its historical numeric value still describes the past, while current lookups reject it. Do not cache a successful lookup or endpoint reference across ticks as evidence of current availability. Provider mutation/discovery/selection stays on the Unity thread; immutable frame reads may occur on other threads.

## Session identity and generations

Tokens contain a random session UUID and an opaque registration counter. The counter is not enumeration-based physical identity. Two identical descriptions, duplicate serials, or identical control paths receive different endpoint tokens. Enumeration reorder leaves existing object-to-token ownership unchanged. A new Unity object, even with a reused runtime ID, gets a new token; the old endpoint remains an invalid tombstone. A returning same Unity object retains its token but starts a new connection generation. Native slots retain only a session endpoint token and increment generation after an observed loss/return; this does not prove the same physical pad returned to that slot.

Connection generations count observed transitions from unavailable/suppressed to provider-connected. They also distinguish backend-authority transitions, not just USB plug cycles. Unsupported controls can belong to a connected endpoint. A transient invalid control read does not itself establish disconnect. Inventory generation changes on endpoint registration, observed connection changes and unavailable-status transitions; numeric value changes alone do not change it. It may advance more than once per publication. Multiple changes between observations may be missed, particularly native reconnects inside the existing half-second disconnected-slot scan interval.

Unity removal/disconnection/disable events immediately publish invalidation without another hardware read. The next tick completes discovery and legacy fallback as before. Native loss is invalidated in the tick that observes it. Disposing publishes all endpoints as unavailable; initialization starts a fresh token session. Known endpoints remain as tombstones for the provider session, so retained inventory grows with runtime endpoint churn; no persistent enrollment or tombstone migration is introduced.

Identity fields record exact Unity description evidence (including driver serial/capabilities), layout and runtime ID, or the native XInput slot. Each field has a source and Reported/Missing/Unsupported status. Description evidence is captured when the endpoint is registered; it is not a continuously refreshed Windows inventory. Reported does not mean validated or unique. Windows interface path, PnP instance, container and physical association are unsupported by this reader, and **all physical resolution remains Unresolved**. Names, serial strings, slots, IDs and ordering are not promoted to physical identity.

`IIdas3ValidatedIdentityEvidenceSource` is only a future adapter contract accepting an endpoint token and connection generation and returning copied, provenance-labelled evidence plus a validation reference. There is no implementation, join algorithm, persistent record ID or automatic use of that contract in this milestone. Validation scope and one-to-one association must be reviewed before an adapter is wired in.

## XInput authority and aliases

The existing policy remains: when any native XInput slot is connected, Unity `XInputControllerWindows` or interface-name `XInput` streams do not contribute samples. Snapshot inventory records them as `SuppressedMirror`; their controls have unavailable values. This is backend-family suppression, not a proven slot-to-Unity-device association. Snapshot-only mirrors do not enter the legacy device list until eligible, preserving its discovery/fallback order.

When all native slots become unavailable, Unity XInput-family devices become eligible on the same refresh path and begin a new sampling connection generation. When native input returns, those Unity streams invalidate again. Missing DLL/entrypoint latches the native backend unavailable until provider reinitialization, matching the legacy behavior. Individual native error codes are recorded as unavailable/read error, not successful zeros. The existing connected-slot polling cadence and half-second scan of disconnected slots remain in use.

No HID is suppressed by VID/PID, serial, label or control activity. A differently exposed HID alias may therefore coexist with an XInput endpoint; its physical association is explicitly unresolved. Do not aggregate these unresolved sources automatically. Incomplete native visibility may conservatively suppress a Unity XInput-family device whose exact native slot is unknown: this is the inherited authority policy, not newly proven alias coverage. Driver mode changes, HID/XInput alternate presentations and slot reassignment still require rig evidence.

## Validation and costs

Portable checks link the actual production provider, snapshot classes, gamepad conversion and binding implementation with minimal Unity surface adapters. A generated test-only copy of the provider from reviewed commit `9f1df2962a5a1023199a8e6fec8827bd4968bd2c` provides differential legacy comparisons. No baseline source is modified. Run:

```text
python3 Tests/DeviceSnapshots/prepare_baseline.py
dotnet run --project Tests/DeviceSnapshots/DeviceSnapshots.csproj --configuration Release
dotnet run --project Tests/ControllerFoundation/ControllerFoundation.csproj --configuration Release
```

Coverage includes distinct duplicate-path devices, duplicate serial/model evidence, immutable collections and retained frames, atomic publication to a concurrent reader, valid zero versus non-finite/unavailable samples, removal before Tick, generation-checked reconnect, runtime-ID reuse, enumeration reversal, unsupported controls, disable/enable, backend suppression/fallback/failure, no VID/PID suppression, disposal/reinitialization, exact native bits and normalization, and actual-provider differential active-device/choices/control comparisons. The existing Controller suite covers cancellation, saved configuration compatibility, capture/reconnect/keyboard guards, evaluated input and unified saving. Portable adapters do not validate Unity serialization, HID report decoding, actual Input System event buffers or Windows APIs.

Allocation is deliberate: live endpoints receive copied sample arrays and small immutable wrappers each tick; identity metadata and unchanged disconnected endpoints are reused. Work is O(known endpoints + live controls). No second hardware polling loop was added; tests count one existing axis read per supported control and the expected native calls. Keeping arbitrary historical frames safe precludes simply reusing a double buffer. Consumers should release old frames when no longer needed. The eight-device/32-controls-each portable fixture measures both baseline and snapshots over 10,000 ticks; results belong to the accompanying run log. Assess GC behavior on the target player before aggregation is enabled; no zero-allocation or Windows frame-time claim is made.
